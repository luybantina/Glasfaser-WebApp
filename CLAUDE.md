# Контекст проекта и перенос на Windows

Это существующее Glasfaser WebApp, версия интерфейса 43.1. Не переписывать
приложение с нуля; сохранять данные, ID записей и учётные записи.

## Текущее состояние

- Worker: https://glasfaser-test.glasfaser-cloud.workers.dev/
- `wrangler.jsonc` относится к действующему исходному аккаунту.
- `index.html` — интерфейс с историческими встроенными JS-патчами.
- `cloud/worker.mjs` — серверный вход, права, API общей базы.
- `cloud/shared.mjs` — diff/three-way merge; `client.mjs` — очередь и опрос.
- `cloud/users.mjs` — статус паролей и управление паролями администраторами.
- `scripts/build.mjs` адаптирует исходный HTML и создаёт `dist/`.
- D1: `records(collection,id,payload)`, ревизия — `meta`.
- Полный `.gfb` формата `GFB-1` включает salt/passHash заданных паролей.
  Браузер получает `hasPassword`, но не парольные хеши. Исходные пароли из
  хешей не восстанавливаются; не сбрасывать их без запроса пользователя.
- Последняя проверка 28.10.2026: пользователей 8, пароль задан у 2.
  Актуальные количества брать из манифеста последнего снимка.

## Задача следующего сеанса

Пользователь планирует перенос 29.10.2026 на Cloudflare другого владельца,
с Windows через Claude. Прочитай `MIGRATION-WINDOWS.md` целиком.

1. Проверить свежесть снимка, SHA-256 и согласовать паузу ввода на старом сайте.
   Если после экспорта работали, получить последний снимок из исходного аккаунта.
2. Установить Node.js 22+, выполнить `npm ci`, `npm test`, `npm run build`.
3. Пользователь сам входит в аккаунт нового владельца. Проверить `whoami`
   и точный account ID. Не копировать OAuth-токены с Mac.
4. Создать `wrangler.account.json` через `npm run cloud:account`, затем НОВУЮ
   D1 с явным `--config wrangler.account.json`.
5. Создать `wrangler.migration.json` через `npm run cloud:target` с новым UUID.
6. Все удалённые команды дальше выполнять с `--config wrangler.migration.json`.
   Обычный `npm run deploy` использует старый аккаунт: не запускать при переносе.
7. Применить схему в новой пустой D1; `npm run cloud:restore` проверит SHA-256,
   пустоту, запрет старого UUID и полное совпадение восстановленных данных.
8. Опубликовать с новой конфигурацией, проверить вход, данные и синхронизацию
   на двух устройствах, передать новый URL.

Старую публикацию/базу не удалять и не изменять. После копирования две базы
автоматически не синхронизируются: параллельный ввод недопустим.

## Windows и проверки

Команды — PowerShell. При блокировке npm.ps1 использовать npm.cmd/npx.cmd,
а не менять системную политику. Для запуска Wrangler из Node использовать
process.execPath и `node_modules/wrangler/bin/wrangler.js`, без shell-строк.

`npm test` использует синтетические данные Miniflare, не рабочую базу.
Команды адаптированы под Windows; реальный Windows-ПК в исходном сеансе
недоступен, поэтому проверить фактический запуск тестов там.

Не коммитить `.private/`, `.gfb`, SQL-дампы, токены. Не печатать содержимое базы
и парольные хеши в лог. Полный снимок и исходники передаются в ZIP закрытого
GitHub Release `migration-2026-10-28`; публичный доступ к нему не включать.
