# Общая облачная база Glasfaser

Опубликовано 28.10.2026: https://glasfaser-test.glasfaser-cloud.workers.dev/

Worker: `glasfaser-test`; D1: `glasfaser-test`
(`62bcea1a-78a0-4e8b-82e0-2773b885c272`). Импортировано 4 404 записи из
`Glasfaser_Backup_2026-10-28.gfb`. Используется существующая авторизация
приложения; рабочие данные не опубликованы в GitHub.

Подготовлен отдельный вариант приложения для Cloudflare Workers + D1. Исходный
`index.html` и работающая публикация GitHub Pages сохраняют прежнее поведение.
Общая база работает по адресу Worker после его публикации. В GitHub Pages
серверной базы нет; всем участникам нужно использовать новый облачный адрес.

## Что реализовано

- Вход на сервере с существующими логинами и паролями из `.gfb`.
- Сеанс на 12 часов в HttpOnly, Secure, SameSite cookie. Блокировка пользователя
  немедленно отзывает его серверный доступ. Есть ограничение попыток входа.
- В настройках сервер передаёт отдельный статус `hasPassword`: отсутствие хеша
  в браузере не означает отсутствия пароля. Администратор может сменить пароль
  и показать вводимое значение. Исходные пароли из хешей не восстанавливаются.
  При смене своего пароля текущий сеанс сохраняется, остальные отзываются.
- Данные и HTML с данными доступны после входа, не кэшируются публично.
  Хеши паролей и salt не передаются в браузер при чтении базы.
- Сохранение изменений отдельными записями в D1 с атомарной проверкой ревизии.
  Одновременная запись со старой ревизией получает конфликт, а не перезаписывает базу.
- Проверка изменений каждые 5 секунд в активной вкладке и при возвращении к ней.
  Во время заполнения формы обновление откладывается до завершения редактирования.
- Разные поля объединяются автоматически. Разные изменения одного поля, а также
  удаление одновременно с редактированием требуют выбора пользователя.
- Очередь неотправленных изменений сохраняется локально. Перезагрузка той же
  вкладки восстанавливает её с объединением с сервером. Копии закрытых вкладок
  можно скачать кнопкой «Копии других вкладок» и восстановить штатным импортом.
- На сервере проверяются права admin/editor/viewer. Импортированные пользователи
  сохраняют свои роли. В текущей резервной копии все 8 пользователей — admin.
- Обновление кода облачной версии выполняется централизованной публикацией.
  Локальная установка `.gfu` в облачной версии отключена.

## Публикация после подключения аккаунта

Требуются Node.js 22+ и аккаунт Cloudflare с правами Workers/D1. Использовать
только принадлежащий заказчику аккаунт. Временный аккаунт для рабочих данных
не подходит.

```sh
npm ci
npx wrangler login
npx wrangler d1 create glasfaser-test --jurisdiction eu
```

Скопировать возвращённый UUID в `database_id` в `wrangler.jsonc`.
Если аккаунтов несколько, явно указать нужный `account_id` в конфигурации.

```sh
npx wrangler d1 migrations apply glasfaser-test --remote
node scripts/prepare-import.mjs /absolute/path/Glasfaser_Backup_2026-10-28.gfb
npx wrangler d1 execute glasfaser-test --remote --file .private/seed.sql
npm test
npm run deploy
```

Импорт предназначен только для пустой новой базы. Повторное выполнение
останавливается с ошибкой вместо замены существующих данных. При прерванном
первоначальном импорте проверить состояние новой базы перед повторной попыткой.
При дальнейших публикациях **не запускать seed повторно**.

Резервная копия и `.private/seed.sql` содержат рабочие данные и хеши паролей.
Они игнорируются Git, имеют ограниченные права на локальном диске и не входят
в статические файлы приложения. Загружать seed только в выбранную закрытую D1.

После публикации проверить вход существующей учётной записью и изменение
тестовой записи на двух устройствах. Изменения в исходном репозитории требуют
прав на запись; публикация Worker из локальной копии от них не зависит.

## Резервные копии и ограничения

Штатная кнопка копирования в браузере сохраняет прикладные данные, но серверные
парольные хеши не включает. Для полного восстановления учётных записей нужна
исходная полная `.gfb` или серверная копия D1:

```sh
npx wrangler d1 export glasfaser-test --remote --output .private/server-backup.sql
```

Не публиковать SQL-копии. Дополнительно доступно восстановление D1 Time Travel
в пределах срока хранения выбранного тарифа.

Для совместимости первоначально используется существующая схема паролей
приложения (salt + 1000 SHA-256). У пользователей сохраняются прежние пароли;
переход на современную схему хеширования потребует отдельной миграции.

Синхронизация опросная, с задержкой примерно до 5 секунд в активной вкладке,
плюс время запроса. Открытие приложения без сети не реализовано. В браузере
остаётся локальная копия данных, как и в исходном приложении.

Большие фотографии и документы могут потребовать отдельного R2-хранилища:
эта версия ограничивает размер отдельной JSON-записи до 1,8 МБ. Текущая
предоставленная резервная копия проходит ограничения. При росте нагрузки нужно
сверить лимиты запросов, CPU и D1 с тарифом Cloudflare; гарантии бесплатного
неограниченного использования нет.

## Проверка

`npm test` проверяет объединение изменений, конфликт полей и удаления,
восстановление очереди, вход, защиту API, параллельные запросы, отзыв сеанса,
права и атомарный откат ошибки в настоящем локальном runtime Cloudflare.

На исходной копии отдельно проверен точный SQL round-trip всех 15 разделов:
4 404 записи, включая 3 614 адресов, 408 работ, 20 встреч и 8 пользователей.
Проверен интерфейс на синтетических данных: вход и обмен изменением проекта
между двумя вкладками.
